## 호스팅 제공업체가 소환장을 받는 경우

| 제공할 수 있음 | 제공할 수 없음 |
|--------------|---------------|
| 통화/메시지 메타데이터(시간, 지속 시간) | 메모 내용, 전사본, 보고서 본문 |
| 암호화된 데이터베이스 blob | 자원봉사자 이름(종단 간 암호화) |
| 어떤 자원봉사자 계정이 언제 활성화되었는지 | 연락처 디렉터리 기록(종단 간 암호화) |
| | 메시지 내용(도착 시 암호화되며 암호문으로 저장) |
| | 복호화 키(사용자의 PIN, 신원 제공업체 계정 및 선택적 하드웨어 보안 키로 보호) |
| | 메모별 암호화 키(임시 — 래핑 후銷毀) |
| | 전화 해시를 역산하는 데 사용되는 HMAC 비밀 키 |

**서버는 읽을 수 없는 데이터를 저장합니다.** 메타데이터(언제, 얼마나, 어떤 계정)는 보입니다. 내용(무엇을 말했는지, 무엇을 썼는지, 연락처가 누구인지)은 보이지 않습니다.

## 기능별 분류

개인정보 노출 정도는 활성화한 채널에 따라 달라집니다.

### 음성 통화

| 사용하는 경우 | 제3자가 접근 가능 | 서버가 접근 가능 | 종단 간 암호화된 내용 |
|-------------|-----------------|----------------|---------------------|
| Twilio/SignalWire/Vonage/Plivo | 통화 오디오(실시간), 통화 기록 | 통화 메타데이터 | 메모, 전사본 |
| 자체 호스팅 Asterisk | 없음(사용자가 제어) | 통화 메타데이터 | 메모, 전사본 |
| 브라우저 간(WebRTC) | 없음 | 통화 메타데이터 | 메모, 전사본 |

**전화 제공업체 소환장**: 통화 상세 기록(시간, 전화번호, 지속 시간)을 보유하고 있습니다. 통화 메모나 전사본은 없습니다. 녹음은 기본적으로 비활성화되어 있습니다.

**전사**: 전사는 자원봉사자의 브라우저 내에서 기기 내 AI를 사용해 완전히 처리됩니다. **오디오는 기기를 절대 떠나지 않습니다.** 암호화된 전사본만 저장됩니다.

### 문자 메시지

| 채널 | 제공업체 접근 권한 | 서버 저장 | 참고 |
|------|-----------------|---------|------|
| SMS | 이동통신사가 모든 메시지를 읽음 | **암호화됨** | 제공업체가 원본 메시지 보유 |
| WhatsApp | Meta가 모든 메시지를 읽음 | **암호화됨** | 제공업체가 원본 메시지 보유 |
| Signal | Signal 네트워크는 종단 간 암호화되나, 브리지는 도착 시 복호화 | **암호화됨** | SMS보다는 낫지만 제로 지식은 아님 |

**메시지는 서버에 도착하는 즉시 암호화됩니다.** 서버는 암호문만 저장합니다. 이동통신사나 메시징 제공업체가 여전히 원본 메시지를 보유할 수 있습니다 — 이는 해당 플랫폼의 한계이며 우리가 바꿀 수 없는 부분입니다.

**메시징 제공업체 소환장**: SMS 제공업체는 메시지의 전체 내용을 보유합니다. Meta는 WhatsApp 내용을 보유합니다. Signal 메시지는 브리지까지 종단 간 암호화되지만, 브리지(사용자의 서버에서 실행됨)는 저장용으로 재암호화하기 전에 복호화합니다. 모든 경우에 **사용자의 서버에는 암호문만 있습니다** — 호스팅 제공업체는 메시지 내용을 읽을 수 없습니다.

### 메모, 전사본 및 보고서

자원봉사자가 작성한 모든 내용은 종단 간 암호화됩니다.

- 각 메모는 **고유한 무작위 키**를 사용합니다(전방향 비밀성 — 하나의 메모가 손상되어도 다른 메모는 안전)
- 키는 자원봉사자와 각 관리자별로 개별적으로 래핑됩니다
- 서버는 암호문만 저장합니다
- 복호화는 브라우저 내에서 이루어집니다
- **사용자 정의 필드, 보고서 내용, 파일 첨부물은 모두 개별적으로 암호화됩니다**

**기기 압수**: 사용자의 PIN **및** 신원 제공업체 계정 접근 권한이 없으면, 공격자는 계산적으로 복호화가 불가능한 암호화된 blob만 얻을 수 있습니다. 하드웨어 보안 키도 사용하는 경우, **세 가지 독립적인 요소**가 데이터를 보호합니다.

## 자원봉사자 전화번호 개인정보 보호

자원봉사자가 개인 전화기로 통화를 받으면, 그 전화번호가 전화 제공업체에 노출됩니다.

| 시나리오 | 전화번호가 보이는 대상 |
|---------|----------------------|
| PSTN 통화 → 자원봉사자 전화 | 전화 제공업체, 이동통신사 |
| 브라우저 간(WebRTC) | 아묏도 없음(오디오는 브라우저 내에 머무름) |
| 자체 호스팅 Asterisk + SIP 전화 | 사용자의 Asterisk 서버뿐 |

**자원봉사자 전화번호 보호**: 브라우저 기반 통화(WebRTC)를 사용하거나, 자체 호스팅 Asterisk에 연결된 SIP 전화를 제공하세요.

## 최근 출시

다음 개선 사항이 현재 적용 중입니다.

| 기능 | 개인정보 보호 이점 |
|-----|------------------|
| 암호화된 메시지 저장 | SMS, WhatsApp, Signal 메시지가 서버에 암호문으로 저장 |
| 기기 내 전사 | 오디오는 브라우저를 절대 떠나지 않음 — 완전히 기기 내에서 처리 |
| 다중 요소 키 보호 | 암호화 키가 PIN, 신원 제공업체, 선택적 하드웨어 보안 키로 보호 |
| 하드웨어 보안 키 | 물리적 키가 원격으로 손상될 수 없는 세 번째 요소 추가 |
| 재현 가능한 빌드 | 배포된 코드가 공개 소스와 일치하는지 검증 |
| 암호화된 연락처 디렉터리 | 연락처 기록, 관계, 메모가 종단 간 암호화 |

| 보고서 | 예(종단 간) | 아니오 | 암호문만 |
| 파일 첨부물 | 예(종단 간) | 아니오 | 암호문만 |
| 연락처 기록 | 예(종단 간) | 아니오 | 암호문만 |

| 팀/역할 메타데이터 | 예(암호화됨) | 아니오 | 암호문만 |

| SMS/WhatsApp/Signal 내용 | 예(사용자 서버상) | 아니오 | 사용자 서버의 암호문; 제공업체가 원본을 보유할 수 있음 |
